# 阶段 1：需求与课程验收基线

状态：阶段 1 规划完成；截至阶段 10，用户、图书、借阅、五项概览统计、Vue 页面及 Nginx 统一入口已纳入 Docker Compose 核心系统。阶段 6 用户取消原统计要求第 6～10 项；阶段 9 暂缓 Redis/NoSQL 缓存；阶段 10 又明确暂缓 Prometheus、Grafana、Kubernetes 与 Istio。这些早期规划仍作为历史设计参考，不属于当前验收版本。项目目标是课程可复现的微服务图书管理系统，而非生产级图书馆平台。阶段 1 的其他设计文档分别说明[架构](architecture.md)、[数据](data-model.md)、[API](api-contract.md)与[借还流程](borrow-workflow.md)。

## 角色与功能范围

普通用户：注册、登录、查看与修改本人资料、查询图书与详情、借还图书、查看本人借阅及状态。管理员：拥有普通用户能力，并能管理用户、图书、分类和借阅，查看五项业务统计。早期规划的系统运行监控页随 Prometheus/Grafana 暂缓。所有授权由后端执行，前端菜单仅改善体验。

管理员对用户、图书、分类提供新增、查询、修改、删除能力。用户和图书的删除采用软删除/归档，历史借阅不被抹除。借阅记录属于业务历史：创建对应借书，读取对应记录查询，更新对应归还或受控更正，删除对应管理员归档；不提供物理清除历史数据的公开接口。此语义必须在 UI 和 API 文档中说明。

## 统计口径

- 用户总数：未归档用户数，包含停用账户。
- 图书总数：状态为 `ACTIVE` 的书目数；另返回仍有可借库存的书目数作为辅助字段。
- 可借图书数量：`ACTIVE` 书目的 `available_count` 之和，单位为册。
- 已借图书数量：借阅状态为 `ACTIVE` 或 `RETURN_PENDING` 的记录数，待确认归还仍占用库存；`PENDING` 不计入。
- 当前借阅数量：仅 `ACTIVE` 借阅记录数。以上五项由管理员概览接口返回；原第 6～10 项已按用户要求移除。

## 现场演示顺序

1. 普通用户登录，执行基础、复合和模糊查询，借书、查记录、还书。
2. 管理员登录，演示用户/图书/分类 CRUD、无效输入、删除确认、统计和系统运行页。
3. 展示 MySQL 分库数据、Compose 容器联动和数据持久化。
4. 当前仅展示 Docker Compose 容器状态、网关转发、三个 MySQL 业务库和数据持久化。Prometheus/Grafana、Kubernetes、Istio 均暂缓。

## 课程项目的简化及限制

一个 MySQL 实例中的三个逻辑库减少部署开销，但实例故障仍会影响三个服务；应用层严格保持数据库归属。统计服务同步调用业务服务 API，不建立消息队列或独立统计库，数据量大时响应延迟可能增加。当前版本不部署 Redis、Prometheus、Grafana、Kubernetes 或 Istio。

阶段 1 曾把 Redis 图书查询缓存、概览缓存和 Redis 容器列为计划；阶段 9 用户将这些内容暂缓，当前验收不测试缓存命中或失效。未来如重新确认，可作为扩展功能加入，但不得改变 MySQL 数据所有权或五项统计范围。

## 待实现阶段固定的业务参数

为避免隐藏假设，阶段 1 曾建议每人最多同时借阅 5 册、借期 30 天。阶段 5 用户已明确确认这两项、逾期不自动罚款且仍允许归还，实际以可配置值实现。管理员改期与自助注册按各阶段已实现接口执行；是否阻止逾期用户继续借书未获单独确认，当前只把逾期 ACTIVE 计入 5 本上限，不额外禁止借书。
