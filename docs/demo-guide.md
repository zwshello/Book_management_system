# 课程现场演示脚本（约 12–14 分钟）

演示目标：用一个管理员和一个普通用户完成管理、查询、借还、五项统计，并证明 gateway、四个业务容器及 MySQL 真正联动。截图若需提交，存放位置与建议文件名见 [screenshots/README.md](screenshots/README.md)。

## 演示前准备（不占现场时间）

1. 在本机准备未提交的 `.env` 和四份服务 `.env`；不要在投屏或截图中展示密码、JWT 私钥、服务令牌。用 `docker compose up --build -d --wait --wait-timeout 180` 启动并确认 `docker compose ps` 七个容器均 healthy。
2. 确认浏览器入口：默认 `http://127.0.0.1:8080/`，若根目录 `.env` 将 `GATEWAY_PORT` 改为 8088，则使用 `http://127.0.0.1:8088/`。
3. 如没有管理员，用 `docker compose exec user-service python manage.py createsuperuser` 交互创建；准备一个临时普通用户。演示时使用自己设置的本地测试密码，不要把密码写入文档。
4. 准备可删除的测试分类和两本图书：借阅用书 ISBN `9787300000145`、总册数 2；归档演示用书 ISBN `9787300000152`、总册数 1。若数据库已有相同 ISBN，现场另选通过 ISBN 校验的唯一值。归档用书应与借阅用书分开，避免影响后续流程。
5. 清理上一轮演示的同名测试数据，或换唯一前缀。保留业务数据时只处理自己创建的临时记录；不要用 `docker compose down -v` 清空数据库。

## 现场讲解重点

- **权限**：普通用户菜单没有管理入口只是体验；后台对用户管理、图书写操作和管理员统计直接请求仍返回 403。
- **协作**：借阅记录只有 `user_id`/`book_id`，扣减和恢复库存由 book-service 的内部 JSON API 完成；statistics-service 只调用三个业务服务的汇总接口。
- **Docker**：容器间用 `user-service`、`book-service` 等 DNS 名，不能用 `localhost`。MySQL 一个容器承载三个逻辑库，但服务账户和表所有权分开。
- **范围**：当前五项业务统计已实现；Redis、Prometheus、Grafana、Kubernetes、Istio 是未来可扩展项，现场不要称为已部署。

演示时若外部服务暂不可用，应展示错误提示和日志，不修改数据库绕过权限，也不展示硬编码假数据。演示后可用 `docker compose down` 停止，保留 MySQL volume。
