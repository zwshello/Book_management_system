# 当前课程版本需求与范围

本页是最终验收版本的需求基线。早期阶段规划见 [phase-1/requirements.md](phase-1/requirements.md)；发生范围变更时，以本页及用户后续确认的阶段要求为准。

## 目标与角色

项目用于“微服务与云原生技术实践”课程专业实习。目标是通过一个可运行的图书管理业务，展示前后端分离、四个独立微服务、REST/JSON 调用、MySQL 数据所有权、JWT 权限以及 Docker Compose 多容器联动。

| 角色 | 能力 |
| --- | --- |
| 普通用户 `USER` | 注册、登录、维护本人允许修改的资料、查询图书与详情、借书、查看本人借阅和还书 |
| 管理员 `ADMIN` | 拥有普通用户能力，并管理用户、分类、图书、借阅记录与五项基础统计 |

管理员授权必须由后端执行；前端路由和菜单只改善使用体验。普通用户提交 `role` 不能给自己提权。

## 当前必做功能

1. 用户：注册、登录、RS256 JWT access/refresh、登出、资料维护、管理员用户 CRUD、启用/禁用、精确和模糊查询、组合筛选与分页。密码由 Django 哈希保存。
2. 图书：分类 CRUD；书目创建、读取、编辑和归档；ISBN 与库存校验；书名、作者、ISBN、分类、状态、可借性查询，支持多条件组合、分页和排序。
3. 借阅：用户与图书经内部 REST API 核验，库存通过 book-service 接口扣减/恢复；本人和管理员分别查询；重复请求使用操作号保证幂等，对部分失败保留可核对状态。
4. 统计：仅有用户总数、图书书目数、可借册数、已借册数、当前借阅数；管理员 Dashboard 和 ECharts 使用真实 statistics-service API 数据。
5. 前端：Vue 3 + TypeScript，角色路由与菜单、表单校验、操作结果提示，以及删除用户、图书、分类前的二次确认。
6. 部署：Vue build 静态服务、Nginx 统一入口、四个 Django 服务、MySQL 8.4，以 Docker Compose 启动；MySQL 使用持久化 volume，容器间通过服务名通信。

用户/图书的“删除”是归档，借阅历史仍保留；分类在无图书引用时物理删除。借阅记录只有管理员可以归档终态记录，不能删除正在进行的借阅。

## 验收证据与边界

- 逐项映射、页面、服务、数据库和现场步骤见 [验收清单](acceptance-checklist.md)。
- 实测环境、140 项后端测试、前端构建、浏览器及 Docker 流程见 [测试报告](test-report.md)。
- **当前课程版本未纳入实现范围的扩展功能**：Redis/NoSQL 缓存、Prometheus、Grafana、Kubernetes、Istio。历史设计中提到它们不代表已经实现，也不作为当前缺陷。
- 本项目是课程演示系统。统计同步调用业务服务；单个 MySQL 实例仍是基础设施单点；未提供生产级高可用、自动调度或集群部署。
