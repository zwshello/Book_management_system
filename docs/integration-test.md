# 阶段 8：前后端联调记录

日期：2026-10-01。范围仅为已实现的 Vue 页面与四个 Django 微服务联调，不引入 Redis 或新业务功能。阶段 8 已完成，以下结果为实际执行记录。

## 环境与方法

- 开发 MySQL：Docker Compose 的 `library-dev-mysql-1`，健康状态已确认。业务服务联调使用独立的 `*_db_test` 数据库；不直接改动现有业务库。
- user、book、borrow、statistics 的隔离联调端口分别为 8101、8102、8103、8104，Vite 使用 5174。浏览器经 Vite 同源代理请求 `/api/v1`，因此本地开发链路不依赖跨源 CORS 许可。代理目标由 `VITE_*_SERVICE_TARGET` 配置；通过 5174 代理实际请求 user-service 登录已返回 200 JSON。
- 四服务 JWT 公钥一致，统计服务身份凭据匹配。JWT 与真实密码只存在未提交的本地环境变量或临时测试数据中。
- 直接跨源访问 book-service 时，401 响应不含 `Access-Control-Allow-Origin`；当前前端请求由 Vite 同源代理转发，实际登录和四组代理 API 已成功，因此不需要在 Django 中放开任意来源。后续网关部署仍应保持同源或明确配置可信来源。
- 集成测试需覆盖实际 HTTP 与浏览器操作；仅通过单元测试或前端构建不足以认定业务流程已联通。

在项目根目录运行 `.\.venv\Scripts\python.exe scripts\verify_phase8_http.py` 可重放隔离数据库的四服务 HTTP 验证。脚本会创建本轮标记数据、启动 8101～8104、执行断言，最后停止服务并清理本轮数据。浏览器联调使用脚本的临时 `--hold` 模式和 5174 Vite 代理，结束后同样完成清理。

浏览器实测：流程 A 完成管理员登录、分类新增、图书新增/列表/编辑，空图书表单及非法 ISBN 给出提示。流程 B 完成管理员创建普通用户、该用户登录、书名模糊/作者/ISBN/分类/可借/排序组合查询、图书详情、借书、我的借阅和还书；库存显示由 2 降为 1，归还后记录为 RETURNED 且按钮禁用。普通用户菜单不含管理员项，直访管理员路由被重定向。

流程 C 的管理员全站借阅页显示真实 RETURNED 记录；管理 Dashboard 在浏览器新建用户/图书并完成借还后变为用户 3、书目 2、可借册数 4、已借册数 0、当前借阅 0。统计页五卡与其一致，ECharts 创建实际 Canvas（1396×540），柱状图高度对应后端返回的 3、2、4 等值，并非硬编码数据。

浏览器删除验证：图书归档弹窗取消后图书仍为 ACTIVE；确认后在架列表 Total 由 2 降到 1。用户归档弹窗取消后账户仍启用。代码路径在 `ElMessageBox.confirm` 成功返回后才调用 DELETE，取消分支不调用 API。重复 ISBN 提交显示后端字段错误 `isbn: ISBN 已存在，包括归档书目。`。非法用户名、邮箱、短密码、非法 ISBN、必填空白均出现前端表单提示；库存输入组件最小值为 0，后端另对负库存返回 400。

## 问题、修复与重测

1. 图书服务本地旧 `.env` 缺 `USER_SERVICE_URL`，配置曾隐式回退到 8001，隔离端口或容器环境会误连。已改为要求显式 URL，并仅给被忽略的本地配置追加缺失地址；配置检查、缺失 URL 测试及完整回归通过。
2. 前端图书列表未提供排序参数；现已加入后端支持的 `ordering`。编辑用户时短密码、纯空白书名/作者等输入的前端提示已修正；后端字段级错误优先显示。借还操作编号按用户隔离，避免切换账户复用；管理列表末页删除后回到有效页码。前端 `npm run build` 已重新通过。

## 尚存问题与阶段 9 注意事项

本阶段未发现阻断 A/B/C 的问题。浏览器没有单独截取排序请求 URL，但排序控件使用后端 `ordering` 参数，HTTP 脚本已实测排序与分页。当前前端使用 Vite 同源代理，直接跨域访问 Django API 不受支持；未来网关仍须保持同源入口或配置明确允许的来源。JWT access 到期后前端统一返回登录页，尚未提供无感刷新；Vite 主包有体积警告。

阶段 9 用户调整范围：当前版本不实现 Redis、NoSQL、图书查询缓存、Dashboard 缓存或 Redis 容器。此项变更不改变本页阶段 8 的测试结果。阶段 10 Docker 化需保留三库的数据所有权、服务间 REST/JSON 调用及现有 A/B/C 验证；库存扣减、借阅状态和权限判断仍以各业务服务及 MySQL 为准。
